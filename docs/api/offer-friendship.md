# API предложений дружбы

Все команды принимают JSON.
Для них используется заголовок Content-Type: application/json.

Текущий пользователь определяется сервером по данным авторизации.
Номера в JSON указывают участников заявки и не заменяют проверку прав.

## Создать предложение дружбы

**Метод и путь:** POST /api/offer-friendships/create

**Кто выполняет действие (actor):** отправитель заявки.

**Над кем выполняется действие (target):** получатель заявки.

**Условия выполнения (preconditions):**
- Оба пользователя существуют.
- Отправитель и получатель являются разными пользователями.
- Текущий пользователь является отправителем.
- Предложение между указанными отправителем и получателем отсутствует.
- Поведение при существующем предложении описано ниже.

### Передаваемые данные

```json
{
  "fromUserId": 1,
  "toUserId": 2
}
```

fromUserId: номер отправителя.
toUserId: номер получателя.

### Результат (result)

Создаётся заявка со статусом PENDING.

### Связанные изменения (side effects)

Отправитель подписывается на получателя.
Дружба пока не создаётся.
Заявка и подписка сохраняются атомарно:
либо сохраняются все изменения, либо ни одно.
Дубликаты подписок не создаются.

### Успешный ответ

Код ответа: 201 Created.

```json
{
  "id": 10,
  "fromUserId": 1,
  "toUserId": 2,
  "status": "PENDING",
  "createdAt": "2026-10-29T10:00:00Z"
}
```

### Ошибки (errors)

#### Предложение дружбы самому себе

Условие: fromUserId и toUserId совпадают.

Код ответа: 400 Bad Request.

```json
{
  "message": "Нельзя отправить заявку в друзья самому себе"
}
```

Заявка и подписка не создаются.

#### Пользователь не найден

Условие: отправитель или получатель не существует.

Код ответа: 404 Not Found.

```json
{
  "message": "Пользователь не найден"
}
```

Заявка и подписка не создаются.

#### Действие от имени другого пользователя

Условие: текущий пользователь не является отправителем.

Код ответа: 403 Forbidden.

```json
{
  "message": "Нельзя отправить заявку от имени другого пользователя"
}
```

Изменения не выполняются.

#### Активное предложение уже существует

Условие: заявка от указанного отправителя указанному получателю
уже находится в состоянии PENDING.

Код ответа: 409 Conflict.

```json
{
  "message": "Активное предложение дружбы уже существует"
}
```

Существующая заявка и подписка сохраняются.
Дубликаты не создаются.

### Повторная отправка

- Если заявка находится в PENDING, возвращается 409 Conflict
  с сообщением "Активное предложение дружбы уже существует".
- Если заявка находится в ACCEPTED, возвращается 204 No Content
  без тела ответа. Существующие дружба и подписки сохраняются.
- Если заявка находится в REJECTED, возвращается 409 Conflict:

```json
{
  "message": "Повторное предложение после отклонения запрещено"
}
```

Повторная команда не меняет состояние заявки
и не создаёт дубликаты связей.

## Принять предложение дружбы

**Метод и путь:** POST /api/offer-friendships/accept

**Кто выполняет действие (actor):** получатель заявки.

**Над чем выполняется действие (target):** предложение дружбы.

**Условия выполнения (preconditions):**
- Заявка существует.
- Текущий пользователь является её получателем.
- Переход в ACCEPTED выполняется из PENDING.
- Обработка других состояний описана ниже.

### Передаваемые данные

```json
{
  "fromUserId": 1,
  "toUserId": 2
}
```

Это участники исходной заявки.
Пользователь 1 отправил заявку, пользователь 2 принимает её.

### Результат (result)

Состояние заявки меняется с PENDING на ACCEPTED.

### Связанные изменения (side effects)

Создаётся взаимная дружба.
Получатель подписывается на отправителя.
Подписка отправителя на получателя сохраняется.

Изменение статуса, создание дружбы и обратной подписки
выполняются атомарно: либо сохраняются все изменения,
либо ни одно.

Дубликаты дружбы и подписок не создаются.

### Успешный ответ

Код ответа: 204 No Content.

Тело ответа отсутствует.

### Ошибки (errors)

#### Заявка не найдена

Код ответа: 404 Not Found.

```json
{
  "message": "Предложение дружбы не найдено"
}
```

#### Действие выполняет не получатель

Код ответа: 403 Forbidden.

```json
{
  "message": "Принять предложение может только его получатель"
}
```

#### Заявка уже отклонена

Код ответа: 409 Conflict.

```json
{
  "message": "Нельзя принять отклонённое предложение"
}
```

При ошибке состояние заявки и существующие связи не изменяются.

### Повторное принятие

Если заявка уже находится в ACCEPTED,
возвращается 204 No Content без тела ответа.
Дружба и подписки сохраняются, дубликаты не создаются.

Если заявка находится в REJECTED,
возвращается описанная выше ошибка 409 Conflict.

## Отклонить предложение дружбы

**Метод и путь:** POST /api/offer-friendships/reject

**Кто выполняет действие (actor):** получатель заявки.

**Над чем выполняется действие (target):** предложение дружбы.

**Условия выполнения (preconditions):**
- Заявка существует.
- Текущий пользователь является её получателем.
- Переход в REJECTED выполняется из PENDING.
- Обработка других состояний описана ниже.

### Передаваемые данные

```json
{
  "fromUserId": 1,
  "toUserId": 2
}
```

Это участники исходной заявки.
Пользователь 1 отправил заявку, пользователь 2 отклоняет её.

### Результат (result)

Состояние заявки меняется с PENDING на REJECTED.

### Связанные изменения (side effects)

Дружба не создаётся.
Подписка отправителя на получателя сохраняется.
Новая подписка получателя на отправителя не создаётся.
Существующие подписки не удаляются.

### Успешный ответ

Код ответа: 204 No Content.

Тело ответа отсутствует.

### Ошибки (errors)

#### Заявка не найдена

Код ответа: 404 Not Found.

```json
{
  "message": "Предложение дружбы не найдено"
}
```

#### Действие выполняет не получатель

Код ответа: 403 Forbidden.

```json
{
  "message": "Отклонить предложение может только его получатель"
}
```

#### Заявка уже принята

Код ответа: 409 Conflict.

```json
{
  "message": "Нельзя отклонить принятое предложение"
}
```

При ошибке состояние заявки и существующие связи не изменяются.

### Повторное отклонение

Если заявка уже находится в REJECTED,
возвращается 204 No Content без тела ответа.
Состояние заявки и подписки сохраняются.

Если заявка находится в ACCEPTED,
возвращается описанная выше ошибка 409 Conflict.
Дружба и подписки сохраняются.

## Получить входящие предложения дружбы

**Метод и путь:** GET /api/offer-friendships/incoming

Возвращает предложения, получателем которых
является текущий пользователь.
В этом контракте возвращаются заявки всех состояний.

Тело запроса отсутствует.
Пользователь определяется по данным авторизации.

### Успешный ответ

Код ответа: 200 OK.

```json
[
  {
    "id": 10,
    "fromUserId": 1,
    "toUserId": 2,
    "status": "PENDING",
    "createdAt": "2026-10-29T10:00:00Z"
  }
]
```

Пример приведён для текущего пользователя 2.
Если предложений нет, возвращается пустой массив [].

Запрос не меняет состояние заявок, дружбу и подписки.

## Общая ошибка авторизации

Для всех операций этого файла:
если пользователь не авторизован, возвращается 401 Unauthorized.

```json
{
  "message": "Необходима авторизация"
}
```

## Принятые проектные решения

Урок не задаёт все детали контракта.
В этом документе выбраны следующие правила:

- Для принятия и отклонения заявка определяется
  по fromUserId и toUserId.
- Текущий пользователь определяется по данным авторизации.
- Успешное принятие и отклонение возвращают 204 No Content.
- Повторное создание при PENDING возвращает 409 Conflict.
- Повторное создание при ACCEPTED возвращает 204 No Content.
- Повторное создание при REJECTED запрещено и возвращает 409 Conflict.
- Входящие и исходящие списки содержат заявки всех состояний.
- Ошибки возвращаются в JSON с полем message.
