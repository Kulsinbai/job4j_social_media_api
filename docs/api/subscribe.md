# API подписок

Текущий пользователь определяется по данным авторизации.
Операции чтения не изменяют данные.

## Получить подписчиков

**Метод и путь:** GET /api/subscribes/followers

**Передаваемые данные:** тело запроса отсутствует.

**Результат:** список пользователей,
которые подписаны на текущего пользователя.

### Успешный ответ

Код ответа: 200 OK.

Пример: пользователи 2 и 3 подписаны на текущего пользователя.

```json
[
  {
    "userId": 2
  },
  {
    "userId": 3
  }
]
```

Если подписчиков нет, возвращается пустой массив [].

## Получить свои подписки

**Метод и путь:** GET /api/subscribes

**Передаваемые данные:** тело запроса отсутствует.

**Результат:** список пользователей,
на которых подписан текущий пользователь.

### Успешный ответ

Код ответа: 200 OK.

Пример: текущий пользователь подписан на пользователей 4 и 5.

```json
[
  {
    "userId": 4
  },
  {
    "userId": 5
  }
]
```

Если подписок нет, возвращается пустой массив [].

## Ошибка авторизации

Для обеих операций:
если пользователь не авторизован,
возвращается 401 Unauthorized.

```json
{
  "message": "Необходима авторизация"
}
```

## Принятые проектные решения

Каждый элемент списка содержит номер пользователя в поле userId.
Такой формат ответа выбран для этого контракта.

Оба запроса не меняют заявки, дружбу и подписки.
Повторные запросы не создают никаких связей.
